Functional programming in C# is a programming style that treats functions as first-class citizens and focuses on writing predictable, composable, and side-effect-free code using concepts like pure functions, immutability, expressions, and higher-order functions. C# is not a purely functional language like Haskell, but it supports many functional programming features through delegates, lambda expressions, LINQ, records, pattern matching, and immutable-friendly design.

🔹 1. Core Idea of Functional Programming

Traditional imperative/OOP programming usually focuses on:

objects + mutable state + step-by-step instructions

Functional programming focuses on:

functions + transformations + immutability + expressions
🔹 Main Principles of Functional Programming
✅ Pure Functions

Same input:

same output always

No side effects.

Example:

int Add(int x, int y)
{
    return x + y;
}
✅ Immutability

Instead of modifying existing data:

create new data

Example:

var newList = oldList.Append(5);

instead of:

oldList.Add(5);
✅ Functions as First-Class Citizens

Functions can:

be stored in variables
passed as parameters
returned from functions

Example:

Func<int, int> square = x => x * x;
✅ Declarative Style

Describe:

what you want

instead of:

how to do it

Example:

var result = numbers.Where(x => x > 10);
🔹 2. Higher-Order Functions

This is one of the MOST IMPORTANT concepts.

✅ Definition

A higher-order function is a function that:

takes another function as parameter
OR
returns another function
🔥 Because functions become values
🔹 Example 1 — Function as Parameter
void Process(int x, Action<int> action)
{
    action(x);
}

Usage:

Process(5, n => Console.WriteLine(n));
🔥 Here:
Action<int>

is a function passed into another function.

Therefore:

Process is higher-order function
🔹 Example 2 — Returning Function
Func<int, int> CreateMultiplier(int factor)
{
    return x => x * factor;
}

Usage:

var doubleIt = CreateMultiplier(2);

Console.WriteLine(doubleIt(5));

Output:

10
🔥 Here:

Function returns another function.

Also higher-order function.

🔹 Why Higher-Order Functions Matter

They enable:

abstraction
reusability
composability
flexible behavior injection
🔹 LINQ is Built on Higher-Order Functions
Example
numbers.Where(x => x > 10)

Where receives:

predicate function

Therefore:

Where is higher-order function
🔹 Common Higher-Order Functions in LINQ
✔ Where

Filtering

.Where(x => x > 5)
✔ Select

Transformation

.Select(x => x * 2)
✔ OrderBy

Sorting

.OrderBy(x => x.Name)
✔ Any

Condition checking

.Any(x => x > 100)
✔ All
.All(x => x.IsActive)
🔹 Functional Composition

Functional programming likes chaining transformations.

Example:

var result = numbers
    .Where(x => x > 10)
    .Select(x => x * 2)
    .OrderBy(x => x);
🔥 This creates pipeline-style programming

Each function:

transforms data
🔹 Lambdas and Functional Programming

Lambdas are central to functional style.

Example
x => x * 2

This is anonymous function object.

🔹 Delegates Enable Functional Programming in C#

Functional programming in C# heavily depends on delegates.

Built-in delegates
Func<T>

Returns value.

Func<int, int> square = x => x * x;
Action<T>

Returns void.

Action<string> print = s => Console.WriteLine(s);
Predicate<T>

Returns bool.

Predicate<int> isEven = x => x % 2 == 0;

Imperative/OOP Style
List<int> evens = new();

foreach(var n in numbers)
{
    if(n % 2 == 0)
        evens.Add(n);

Functional Style
var evens = numbers.Where(x => x % 2 == 0);
🔥 Functional code emphasizes transformations
🔹 Immutability in Functional Programming

Functional programming avoids:

changing existing state

Instead:

create new values
❌ Mutable

🔹 Side Effects in Functional Programming

Functional programming tries minimizing:

console output
database writes
mutable globals
external changes

Because:

pure functions easier to reason about
🔹 Expression-Oriented Style

Functional style prefers:

expressions over statements
Example
int result = condition ? 5 : 10;

instead of:

if(condition)
    result = 5;
else
    result = 10;
🔹 Records Help Functional Programming

Records support:

immutability
value equality
non-destructive mutation

Example:

var p2 = p1 with { Age = 30 };
🔹 Pattern Matching Helps Functional Style
var result = number switch
{
    > 0 => "Positive",
    < 0 => "Negative",
    _ => "Zero"
};
🔹 Real Functional Philosophy

Functional programming treats programs as:

data flowing through transformations

instead of:

objects changing state over time

⚡ Final Comprehensive Summary (your style)

Functional programming in C# is a programming style focused on pure functions, immutability, declarative transformations, and treating functions as first-class citizens that can be passed, stored, and returned like normal values. It emphasizes predictable behavior, minimal side effects, and composing operations through pipelines of transformations instead of step-by-step mutable logic. Higher-order functions are functions that take other functions as parameters or return functions as results, enabling abstraction and flexible behavior injection. LINQ methods like Where, Select, and OrderBy are classic examples of higher-order functions in C#.
